# 中文 DOCX 交付前检查清单

调用本技能后，按顺序完成结构检查，再完成渲染检查。检查项不因文档较短而跳过；条件模块只检查实际存在的内容。

## 一、模式和来源

- [ ] 已判定论文模式或通用正式文档模式。
- [ ] 模式无法判断时已只询问一次并记录答案。
- [ ] 已采用用户模板或空白基线模板，并能验证默认基线标识。
- [ ] 没有直接复制参考论文的正文、个人信息、学校信息、嵌入对象、域结果或元数据。
- [ ] 用户明确规范与模板冲突时，已以用户明确规范为准。
- [ ] 格式化已有 DOCX 时使用迁移脚本，并将输出写入不同路径：`python scripts/format_chinese_docx.py 输入.docx --output 输出.docx --profile auto`。

## 二、页面、节和页码

- [ ] 所有正文节为 A4 纵向。
- [ ] 上、左、右边距为 2 cm，下边距为 2.7 cm。
- [ ] 没有用空格、空段落或文本框模拟边距。
- [ ] 没有不必要的固定页眉。
- [ ] 页码在页下居中，字体默认为五号 Times New Roman。
- [ ] 正文开始节页码从 1 开始。
- [ ] 前置内容按需要使用独立节，未错误显示正文页码。
- [ ] 节分隔没有造成意外空白页或页眉页脚继承。

## 三、样式和段落

- [ ] 存在并实际使用 Normal、Title、Heading 1、Heading 2、Heading 3 样式。
- [ ] 正文为小四号宋体，英文及拉丁字符为 Times New Roman。
- [ ] 普通正文两端对齐，首行缩进两字符，1.5 倍行距；代码、接口路径和技术标识使用左对齐样式。
- [ ] 文档标题为三号黑体、居中，最多两行。
- [ ] Title/Heading 段落样式及其关联字符样式都没有主题色、边框、底纹、下划线或装饰横线。
- [ ] Normal、Title、Heading 1/2/3 没有错误的加粗、倾斜、保持或分页继承；只有 Heading 1 默认段前分页。
- [ ] 标题和正文间距由样式控制，没有连续空白段。
- [ ] 直接段落和直接字符格式的数量已经审计；异常集中项已处理或报告。
- [ ] 没有固定行高导致文字截断。
- [ ] Code Block 左对齐并关闭拼写检查，正文中的普通路径没有被误判为代码块。

## 四、标题和目录

- [ ] 一级、二级、三级标题分别使用真实 Heading 1、Heading 2、Heading 3。
- [ ] 一级、二级、三级标题字号分别为三号、四号、小四号黑体。
- [ ] 一级、二级标题居中，三级标题左对齐。
- [ ] 论文标题没有手工重复编号。
- [ ] Heading 1 至 Heading 3 绑定同一个模板内置多级编号定义，并核对 `numId → abstractNum → numFmt` 完整链路。
- [ ] 一级编号的中文数字与二、三级的阿拉伯数字通过 `isLgl` 兼容规则连接，正文和目录不会出现“二.1”与“2.1”不一致。
- [ ] 没有标题级别跳跃或编号倒退。
- [ ] 需要目录时存在真实 TOC 字段，范围覆盖 1 至 3 级。
- [ ] 目录排除了“目录”自身及图表目录标题。
- [ ] 目录页码已在 Word 中更新，或已明确标记为待更新。

## 五、条件模块

### 中文摘要

- [ ] 仅在存在摘要内容时生成摘要模块。
- [ ] 标题为“摘 要”，三号黑体，居中。
- [ ] 摘要正文为四号宋体，首行两字符，标题后空一行。
- [ ] 关键词为四号黑体标签加中文冒号，正文为四号宋体。
- [ ] 关键词数量为 4 至 6 个，分号分隔，最后一个无标点。

### 英文摘要

- [ ] 仅在存在英文摘要内容时生成英文摘要模块。
- [ ] ABSTRACT 居中，正文前空两行。
- [ ] 英文正文为四号 Times New Roman，每段首行四字符。
- [ ] KEYWORDS 后的关键词为小写英文，分号分隔，最后一个无标点，正文后空两行。

### 图和表

- [ ] 图题、表题为中文五号楷体，居中。
- [ ] 图号、表号按章连续，未手工跨章维护错误数字。
- [ ] 图题没有擅自附加英文翻译。
- [ ] 图像优先为行内对象，未发现不必要的浮动锚点。
- [ ] 图像清晰、没有裁切、拉伸或越界。
- [ ] 表格总宽度不超过版心，有外框和内部网格线，长表格表头跨页时重复。
- [ ] 表格行高自动扩展，单元格有合理内边距，单位清楚。
- [ ] 图题与图、表题与表没有跨页失配。

### 公式

- [ ] 公式均为原生 OMML，可编辑、可复制。
- [ ] 没有残留 MathType OLE、原始 LaTeX 或公式图片。
- [ ] 公式另起一行，主体居中，序号右对齐。
- [ ] 公式序号按章连续；附录公式与正文分开。

### 引用和参考文献

- [ ] 正文引用格式一致，默认使用全角方括号数字。
- [ ] 引用序号与参考文献条目一一对应。
- [ ] 参考文献按正文首次出现顺序连续编号。
- [ ] 作者、题名、文献类型、出版信息和页码只使用用户提供的数据。
- [ ] 缺失字段已报告，没有臆造。
- [ ] 参考文献使用悬挂缩进的 Reference 样式，未使用 EndNote 专用依赖。

### 附录

- [ ] 仅在存在附录内容时生成附录。
- [ ] 附录按附录 1、附录 2……编号。
- [ ] 附录标题使用 Appendix Heading 样式和独立编号定义，没有手工重复编号。
- [ ] 附录图、表、公式与正文分开编号。

## 六、结构审计

使用 bundled Python 运行：

    python scripts/audit_chinese_docx.py 输入.docx --profile auto --require-baseline --json 审计报告.json

- [ ] 审计完成且没有未解释的错误。
- [ ] 警告已经区分为“需用户补内容”“需 Word 更新字段”“仅视觉可确认”。
- [ ] 审计报告没有自动修改源文件。
- [ ] 对空白基线模板执行过审计。
- [ ] 用一个合格样例检查过正文、三级标题、摘要、目录、图表、OMML 公式、参考文献和附录。
- [ ] 用一个故意错误样例确认边距、字体、行距、标题层级、编号、关键词数量和引用格式可以被发现。

## 七、视觉验收

如果 Windows Microsoft Word 可用：

- [ ] 使用 `scripts/render_docx_windows.ps1` 导出 PDF，并把 PDF 转为 `page-N.png`。
- [ ] 每一页以 100% 进行检查。
- [ ] 没有缺字、乱码、重叠、裁切、溢出、孤立标题或页码错位。
- [ ] 目录、图表、公式和跨页表格均可读。
- [ ] 修改后重新渲染并检查了最新版本。

如果 Microsoft Word 不可用：

- [ ] 交付中明确写出“视觉验收未完成”。
- [ ] 没有宣称“版式已视觉通过”。
- [ ] 结构审计结果与视觉限制分开报告。
