# 中文 DOCX 非内容格式控制

本技能只负责 DOCX 的非内容格式。除非用户明确要求，不改写事实、论证、数据、引用内容或作者语气。
本技能包含可执行的迁移脚本；只写一段“请把字体改好”的提示词，不能视为完成排版。

## 强制规则

调用本技能后，必须执行以下规则，不得把它们当作可选建议：

1. 先判断工作模式：
   - 论文模式：用户明确要求毕业论文、学位论文、论文格式，或文档同时出现摘要、目录、章标题、参考文献等论文结构信号。
   - 通用正式文档模式：正式报告、方案、制度、说明书等，但没有足够论文结构信号。
   - 无法判断时，只询问一次“按论文模式还是通用正式文档模式处理”，得到回答后继续。
2. 权威顺序固定为：用户本轮明确规范 > 用户明确提供的新模板或学校规范 > 本技能规范 > 参考论文中补充提炼的细节。参考论文只用于观察格式，不复制正文、个人信息、学校信息、批注、域结果或嵌入对象。
3. 必须从用户明确提供的模板或本技能的空白基线模板开始。不得把参考论文直接另存为新文档。使用本技能基线时，输出文档必须保留基线标识；没有用户模板且无法验证基线来源时，不得宣称模板已生效。
4. 输入 DOCX 只读处理，输出到新文件。不得覆盖原文档，也不得用“原文另存为”替代从模板创建目标文档。已有内容应迁移到目标文档，并按语义映射到规范样式。
5. 优先修改 Word 样式、节属性和编号定义；不得用逐段直接格式化来伪造统一版式。正文标题必须使用真实的 Heading 1、Heading 2、Heading 3 样式。
6. 章、节、小节必须使用模板内置多级编号。模板使用 `chineseCounting + isLgl`：一级显示“第一章”，二级和三级显示“1.1”“1.1.1”。不得接受或交付“二.1”这类混合编号。标题文本只写标题本身，不手工重复写编号。
7. 文档标题、一级标题、二级标题和三级标题只使用黑体，不设置加粗；一级标题居中，二级和三级标题均左对齐。标题样式及编号级别必须同时清零首行缩进、左缩进和制表位。
8. 已有 DOCX 必须优先使用 `scripts/format_chinese_docx.py` 迁移到新输出文件；不得先复制源文档样式再局部修补。新文档使用 `assets/chinese-docx-base-template.docx`。
9. 摘要、英文摘要、目录、图表目录、参考文献和附录都是条件模块。没有对应内容时不得生成空标题或占位段落。
10. 参考文献只能格式化用户提供的信息；缺少作者、年份、卷期、页码等信息时保留缺失并报告，不得联网臆造。
11. 公式的目标格式必须是原生可编辑 OMML。模板不得携带 MathType/OLE 公式；输入文档若已有旧 OLE，为避免内容丢失可以原样保留，但必须在审计报告中标记，不能宣称其已转换为 OMML。
12. 图像优先使用行内对象；表格必须设置版心内的合理列宽、可扩展行高、可见网格边框和跨页重复表头；不得用固定行高制造截断风险。
13. 完成后必须运行结构审计。Windows 有 Microsoft Word 时，必须使用本技能的 Word 原生 PDF 渲染脚本，再把 PDF 转为 PNG 并逐页检查；不把 LibreOffice 作为硬依赖。没有可用渲染器时可以结构交付，但必须明确写出“视觉验收未完成”，不得宣称版式已视觉通过。

在 Windows 上，Microsoft Word 是 DOCX 视觉验收的首选基准；LibreOffice 只能作为可选备用渲染器，不能用来掩盖未完成的 Word 验收。

## 默认基线

- A4 纵向；上、左、右页边距 2 cm；下页边距 2.7 cm。
- 通用模式不设置固定页眉；论文模式保留用户输入的页眉文字（不虚构学校或学位信息），页眉距 1.5 cm、页脚距 1.75 cm，并启用论文首页与奇偶页眉节属性；页码页下居中。
- 文档标题使用 Title 样式，三号黑体、不加粗，居中，最多两行，无下划线、边框和装饰线。
- 正文使用 Normal 样式：小四号宋体，英文及拉丁字符 Times New Roman，两端对齐，首行缩进两字符，1.5 倍行距。代码、接口路径、字段名和其他技术标识使用 Code Block 或等价左对齐样式，不强行两端对齐。
- 不启用文档网格、字符间距压缩或标点压缩；不使用空格、制表位和空段落模拟版式。
- 一级、二级、三级标题分别为三号、四号、小四号黑体，均不加粗；一级居中，二级和三级左对齐；使用真实 Heading 样式，并清除标题首行缩进、左缩进和制表位。一级标题使用 1.5 倍行距、段后 1 行；二级和三级使用 1.5 倍行距，段前段后均为 0。
- 页码使用五号 Times New Roman；所有模式正文页码从 1 开始，不启用前置罗马数字页码；没有额外前置节时不生成空白前置页。
- 中文图题、表题和图表目录条目默认使用五号楷体、居中或目录所需的左对齐，行距 1.25 倍，不自动增加英文翻译。
- 正文引用默认使用行内全角方括号数字，例如“［1］”。

## 执行流程

1. 读取输入 DOCX 的结构和现有样式，识别论文模式或通用模式；记录正文、表格、图像、公式和字段数量，先保护已有内容。
2. 选择用户模板或 assets/chinese-docx-base-template.docx。需要参考论文时，仅提取版式事实，不复制其内容。已有 DOCX 必须迁移到目标模板，而不是在原包上打补丁。
3. 格式化已有 DOCX 时执行：

       python scripts/format_chinese_docx.py 输入.docx --output 输出.docx --profile auto

   脚本只读输入，以空白基线模板承载迁移后的内容，清除源样式、源节属性和视觉覆盖，按语义映射段落，保留正文、表格、图片和 OMML；输出路径必须不同于输入路径。源文档已有的 MathType/OLE 等对象不由迁移器伪装转换，审计会明确标记。
4. 先建立或修正节、页面、字体、段落、标题样式和多级编号，再写入内容。所有可重复的格式必须落在样式上；清除旧文档的主题字体、关联字符样式和标题装饰残留。
5. 按条件创建摘要、英文摘要、目录、图表、公式、参考文献和附录。目录使用真实 TOC 字段；公式使用 OMML；编号使用字段或编号定义。表格完成版心宽度和列宽检查后再交付。
6. 运行只读审计：
   python scripts/audit_chinese_docx.py 输入.docx --profile auto --require-baseline --json 审计报告.json
7. Windows 有 Microsoft Word 时，运行 `scripts/render_docx_windows.ps1` 导出 PDF，再用 Poppler 将 PDF 转为 PNG，逐页检查。字段、目录和页码在 Word 中可能需要更新；结构审计不能替代视觉验收。
8. 交付前报告模式、实际执行的检查、视觉验收状态、内容/对象保留结果，以及没有被改动的原始文件。结构审计通过不等于视觉通过；无可用 Word 时必须写明“视觉验收未完成”。

## 模式差异

论文模式严格执行 references/format-spec.md 中的论文专用规则。通用模式执行同一套页面、样式、表格、图题、公式、页码和引用基线；文档实际采用三层章节结构时，保留章节编号和一级标题分页，但不得为了“看起来完整”强行生成摘要、目录、章节或参考文献。
